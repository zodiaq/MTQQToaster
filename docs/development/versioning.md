# バージョン管理

[ドキュメント一覧](../README.md) · [MSIXパッケージ手順](msix.md)

バージョンは `a.b.c.d` の4要素（quad version）で管理します。

- `a`：メジャー。破壊的変更でインクリメントします。
- `b`：マイナー。機能の追加・削除でインクリメントします。
- `c`：ビルド。セットアップを作成するたびに必ずインクリメントします。
- `d`：リビジョン。通常は `0` とします。

セットアップ作成前に採番し、同じバージョンのセットアップを再配布用に作り直す場合も `c` を増やします。通常のコンパイルやテストだけでは `c` を増やしません。今回のルール導入では `1.0.0.0` から `1.0.1.0` に更新します。

## 更新手順

1. `CMakeLists.txt` の `project(... VERSION ...)` を4要素で更新します。
2. `vcpkg.json` の `version-string`、`resources/app.rc` の数値・文字列バージョン、`resources/app.manifest` と `packaging/AppxManifest.xml` のバージョンを同じ値へ更新します。
3. `scripts/create-dev-setup.ps1` を実行します。セットアップのバージョンは `CMakeLists.txt` から読み取り、MSIX、ZIP名、同梱手順へ反映します。採番は自動ではなく、この手順で行います。
4. Releaseビルド、CTest、MSIX作成、署名検証の成功を確認します。生成物はコミットしません。

各要素はWindowsパッケージで扱える `0`～`65535` の範囲とし、メジャーは `1` 以上にします。上限に達した場合は桁あふれや同一番号の再利用をせず、次の採番を決めます。
