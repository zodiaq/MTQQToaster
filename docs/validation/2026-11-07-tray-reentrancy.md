# トレイ右クリック時のXAML再入クラッシュ

[検証記録一覧](README.md)

## 障害と原因

固定サイズ設定画面とXAMLメニューの導入後、実際のトレイ右クリックでWindows.UI.Xaml.dll内のアクセス違反（0xc0000005、続いて0xc000041d）が発生した。

ユーザー操作で診断版を再現させたところ、例外スタックにはXAML初期化、UiaManager／COMの呼び出し、ネストしたウィンドウ通知、同じメニュー表示処理への再入が記録された。初回表示が完了する前に再びXAML初期化へ入ることを防止していなかった。単独プレビューや順次通知の試験ではこの条件を作れていなかった。

## 修正

ShowTrayMenuの入口に再入ガードを追加した。表示処理中の重複通知は処理済みとして扱い、最初の表示処理を継続する。例外時を含め、スコープ終了時にガードを解除する。角丸・アイコン・明暗対応のメニューは維持する。

診断に一時使用した例外スタック記録ハンドラーは製品ビルドから除去した。

## 検証

Windows 11、x64 Release、未コミット作業ツリーで確認。

- `--tray-smoke-test`：設定監視を開始し、別スレッドからトレイ通知を送信。UIスレッドのCBTフックからウィンドウ生成中に通知を再送し、初期化中の再入を強制する。
- 同じ回帰試験で再入ガードを一時的に除いた対照版は終了コード0xc000041dでクラッシュした。
- ガードを戻した修正版は終了コード0。初回表示、再表示、設定画面への遷移と終了を確認。
- ユーザーが修正版の診断トレイを実際に右クリックし、「メニューが表示された」と確認。
- 標準Releaseのビルド成功、`ctest --preset x64-release`の29件成功、同EXEの`--tray-smoke-test`終了コード0を確認した。診断版を停止して通常の常駐アプリを修正版で再起動した。

診断用トレイの試験は実設定やMQTT通信を使用しない。通常の設定監視以外の通信機能は変更していない。
