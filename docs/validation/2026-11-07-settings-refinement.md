# 固定サイズ設定画面とトレイメニュー

[検証記録一覧](README.md)

## 対象と環境

2026-11-07の未コミット作業ツリー。Windows 11、MSVC 19.51、Windows SDK 26100、x64 Release。静的CRTとx64-windows-staticを維持した。OS内蔵XAMLとWICを使用し、新しい配布ランタイムは追加していない。

## 結果

- 検証用ビルド `cmake --build out/build/xaml-validation --config Release`：成功。
- 検証後に常駐中の標準Releaseを停止し、`cmake --build --preset x64-release`で更新・再起動した。再起動後のプロセス継続を確認。
- `ctest --test-dir out/build/xaml-validation -C Release --output-on-failure`：29件成功。
- `--ui-smoke-test-ja` と `--ui-smoke-test-en`：終了コード0。固定ウィンドウスタイル、位置復元、全体レイアウト、新規項目を選んで追加、擬似新規項目の削除防止、画像解除、保存・キャンセル、メニューの生成・再表示・非表示、設定監視の再読み込みと終了を確認。
- 実画面：日本語・英語で全コントロールと保存・キャンセルが表示され、画面全体のスクロールバーがないことを確認。タイトルバーは閉じるボタンのみ。
- 実画面：`<新規>`の選択で入力欄が空になり、「更新」でトピックが追加された。リポジトリ内のpackage-icon.pngを指定し、フォーカス移動後にサムネイルが描画された。
- メニュー専用プレビュー：日英のアイコン付き表示、上下キー移動、Enterで設定画面へ遷移、設定画面のEsc終了を確認。通常のツールウィンドウは検証ツールの列挙対象外のため、プレビューだけ通常ウィンドウとして表示し、非アクティブ化で閉じないようにした。
- `git diff --check`：エラーなし。

## 診断と未確認事項

標準ReleaseのEXEが常駐中で初回リンクに失敗したため、先に別ディレクトリで検証した。サンドボックス内の初回UI起動はアクセス拒否で失敗し、対話セッションで再実行した。途中の設定監視試験は一度再読み込み待ちがタイムアウトした。その後の英語試験、日本語最終試験、英語最終試験では成功したが、単発タイムアウトの原因は特定していない。期待値や待機上限は緩和していない。

Windows 10、実際の高コントラスト切り替え、混在DPI・小さい作業領域、MSIXのスタートアップ項目、スクリーンリーダー、通常メニューの外側クリックによる終了は実機未確認。検証では利用者のWindows設定やスタートアップ登録を変更していない。角丸はDWMの指定であり、OS側の合成ポリシーに依存する。
