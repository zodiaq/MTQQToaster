# 2026-11-07：OS内蔵XAML設定画面の検証

[検証記録一覧](README.md) · [採用判断](../decisions/0002-os-xaml-settings.md)

## 対象・環境

この作業ツリーの設定UI変更。Windows 11（ビルド26300）、MSVC 19.51、Windows SDK 10.0.26100.0、CMake 4.4.4、x64-windows-static。Releaseは標準プリセット、Debugは起動中の旧Debug版を上書きしないよう別出力先`out/build/xaml-validation`で検証した。

## 結果

- Releaseビルド成功。`ctest --preset x64-release`は26件成功。
- Debugビルド成功。`ctest --test-dir out/build/xaml-validation -C Debug --output-on-failure --no-tests=error`は26件成功。
- 両構成の`--ui-smoke-test`が終了コード0。初回表示、配置・サイズの復元、配置初期化、トピック追加・更新・削除、画像解除、保存、キャンセル、設定再読込、監視初期化中の終了を確認。
- 両構成の`MTQQToasterXamlProbe`が終了コード0。OS内蔵XAMLの標準部品とislandの3回生成・破棄を確認。
- プレビューでカード配置、全設定項目、日本語文字列入力、Tab／Shift+Tab、キャンセルとAlt+F4による終了を確認。最終の角丸・Tab循環・Esc対応後の追加画面操作は、ユーザーの物理EscによるComputer Use停止で終了した。
- Release EXEは1,719,808 bytes。生成プロジェクトでReleaseのMultiThreaded、DebugのMultiThreadedDebugを確認。
- `dumpbin /dependents`の直接依存はWindows標準DLL。XAML表示後にWindows.UI.Xaml.dllとWindows.UI.Xaml.Controls.dllをSystem32から読み込むことを確認。調査対象のvcruntime／msvcp／coreclr／Windows App SDK関連モジュールでは、OS標準のmsvcp_win.dll以外のCRTや.NET／Windows App SDKランタイムは観測しなかった。開発PC上の結果であり、クリーン環境での動作保証ではない。

## 検出し修正した問題

- フォーカス移動イベントからの再入で初回表示に失敗。再帰する移動処理を除去し、標準のTab循環を使用。
- 最終islandを各閉じる操作で破棄すると、設定監視の再読込がタイムアウト。変更前の既存Debugバイナリでは同試験が成功した。islandを非表示で保持してアプリ終了時に解放する構成で成功。
- 監視のCancel直後はStatusがCanceledでも初期化コルーチンがまだ終了しておらず、試験用フォルダー削除後にエラーが発生。コルーチンのスコープ終了を明示的に待つよう修正。最終Debug／Release試験では同エラーなし。
- 標準Debug出力は起動中の旧アプリによりリンク不可。別出力先でビルド・検証し、旧アプリは停止していない。
- app_logic.cppの既存の型変換・未使用変数警告、fmtの到達不能コード警告は残る。今回の設定UIソースのコンパイルエラーは解消。

## 未確認

開発ツールのないWindows、Windows 10 1903、署名済みMSIXのインストール・更新、実IMEの変換候補操作、異なるDPIのモニター間移動、テーマ／ハイコントラスト切替、最小サイズでの全操作は未確認。実ブローカー・実トースト・ローカルTLS結合試験は今回のUI変更の検証対象外。実設定や認証情報は試験に使用していない。

非MSIXのXAML Islandsには公式にVisual C++ Runtime要件が記載されているため、「静的CRTならすべての配布先で追加インストール不要」とは断定しない。
