## 更新ルール

1. 同じ事実の詳細は一か所に置き、他の文書から相対リンクで参照します。
2. 機能変更時は現行仕様・該当リファレンス・操作手順を更新します。判断の理由は設計記録へ分離します。
3. 試験の実行方法はテスト手順へ、実行結果は日付付き検証記録へ書きます。過去の結果を再実行したかのように更新しません。
4. 検討メモは`decisions/`へ状態付きで置きます。採用後は現行資料へ反映し、記録には経緯を残します。
5. 一時的な作業ログ、チャットの転記、個人環境の絶対パス、認証情報、生成物は公開資料へ追加しません。
6. 文書を追加したら、この索引またはカテゴリ索引からリンクします。各文書に親へのリンクを設け、GitHub上で孤立させません。
7. 移動時は既存リンクを更新します。従来の入口である`SPECIFICATION.md`と`docs/mqtt-transport.md`は維持します。
8. 日本語を基本とし、識別子は原表記を使います。追記で責務が増えたら分割し、READMEへ詳細を戻さないでください。
